## Overview

A 620px-tall scroll stage containing three equal-width columns. The center column scrolls downward (normal direction) while the two flanking columns scroll upward (reverse direction). All three loop infinitely. A control panel lets the user adjust the side-column speed multiplier to feel how ratio changes affect the illusion.

## Infinite Loop Mechanic

Each `col-inner` contains **two identical card sets** stacked vertically:
```
[set A — 12 cards]   ← singleSetH px
[set B — 12 cards]   ← singleSetH px
Total height = 2 × singleSetH
```

`singleSetH` is measured from the DOM after card generation:
```js
const singleSetH = colInner.firstElementChild.offsetHeight;
```

### Side columns (scroll UP — left and right)

`col-inner` starts at natural position (no margin offset).

```js
const rawOffset = scrollTop * Math.abs(mult);
const offset    = rawOffset % singleSetH;          // 0 → singleSetH
translateY      = -offset;                          // negative = upward
```

At `offset = 0`: set A visible (y=0), set B below.
At `offset = singleSetH`: inner moved up by one full set → set B is now at y=0, identical to set A → seamless wrap → `offset` modulos back toward 0.

When `mult > 0` (user drags slider to positive): side columns move DOWN instead. Formula becomes `translateY = +offset` (downward). The DOM structure is the same; the sign changes.

### Center column (scroll DOWN)

`col-inner` has `margin-top: calc(-1 * var(--single-set-h))` applied via CSS custom property set by JS.

```js
centerInner.style.setProperty('--single-set-h', singleSetH + 'px');
```

```css
.col-inner.center { margin-top: calc(-1 * var(--single-set-h)); }
```

```js
const offset = scrollTop % singleSetH;   // 0 → singleSetH
translateY   = +offset;                  // positive = downward
```

At `offset = 0`: set B visible (set A is margin-top'd above viewport). As offset grows, inner moves down, set A slides into view from the top. At `offset = singleSetH` → wraps back to 0 → set B is in view again. Seamless. ✓

### Direction summary at mult = −1.0 (default)

| Column | Direction | Formula |
|--------|-----------|---------|
| Left   | UP | `translateY = -(scrollTop % singleSetH)` |
| Center | DOWN | `translateY = +(scrollTop % singleSetH)` |
| Right  | UP | `translateY = -(scrollTop % singleSetH)` |

## Speed Multiplier

Slider range: −2.0 to +2.0, step 0.1, default −1.0.

- `mult < 0` — side columns go UP (reverse, classic effect)
- `mult = 0` — side columns stationary
- `mult > 0` — side columns go DOWN (same direction as center; effect breaks)
- `mult = −1.0` — side columns match center speed exactly but opposite direction

Side column offset formula (unified):
```js
const magnitude = Math.abs(mult);
const rawOffset = scrollTop * magnitude;
const offset    = rawOffset % singleSetH;
const direction = mult >= 0 ? 1 : -1;
translateY      = direction * offset;       // ±offset
// Note: center col DOM uses margin-top trick; side col DOM does not.
// For mult > 0, side col inner moves DOWN from y=0 — no wrap-around from above,
// but scroll range (1380px) gives 1+ full loops for mult ≤ 1.0, which is enough for demo.
```

## Controls Panel

Layout: right of stage on desktop (`clamp(200px, 22vw, 240px)` wide), stacks below on mobile.

Contents (top to bottom):
1. **Educational note** — "The illusion of the side columns 'flowing the other way' is purely visual — they're scrolling at the same speed as your input, just in the opposite direction. Setting the multiplier to +1.0× makes them move with you and the effect disappears."
2. **Scroll progress** — live `%` readout
3. **Offset table** — Left / Center / Right current `px` offset (3 rows)
4. **Speed multiplier slider** — `<input type="range" min="-200" max="200" step="10" value="-100">`, displayed as `(value/100).toFixed(1) + '×'`
5. **"Match direction" toggle** — when checked, forces `mult = +1.0`; uncheck restores slider
6. **Reset button** — snaps `stage.scrollTop = 0`, restores mult to −1.0, unchecks toggle

- `motionMQ.matches` re-read on every scroll event (live, not snapshot)
