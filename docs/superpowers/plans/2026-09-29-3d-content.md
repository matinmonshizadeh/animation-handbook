# 3D & Advanced — Content Sheet

This sheet decides, page by page, how the eighteen 3D & Advanced pages present their kind, settings, words and prompt on the guided-steps page. The conversion tasks of `2026-09-29-demo-page-rollout-parallel.md` follow each section exactly, together with "How to convert a page" in `2026-09-28-demo-page-rollout-text-typography.md`, the markup for the do-it and scroll kinds in `2026-09-29-demo-page-kinds-do-and-scroll.md` (Tasks 1–3), and the lessons in the rollout's Global Constraints. Rotate In (`animations/02-entrance-and-exit/rotate-in/`) is the reference for everything a section does not mention. Text on a Path is the reference for a loop driven by animation frames, and Glitch Text and Wavy Text for "css" loops.

A page is a loop when something on it moves by itself with no end, even if the pointer also plays a part (the pointer then appears in the help line). A page is a do-it page only when nothing moves until the visitor or Show me moves it: a do-it page has no Pause, so under reduced motion anything that moved by itself could not be stopped. Every page keeps settings, so every page has a Try it step. Of the rollout spec's special cases, only "click demos play one click and return to rest" concerns this category (3D Flip Card).

How to read a section:

- **Sets in the demo** lists one value per choice, in the same order as the choices. A Speed row sets the script's variable and the CSS variable it names.
- **Shown only when …** in the Control column means the setting's whole `div.hb-setting` gets the `hidden` attribute while it has no effect, so it also drops out of "Your settings".
- Switches in Try it keep their default in the markup (`checked` when the default is on), as on Rotate In. Only the player bar's switches (Loop, Slow motion) start unchecked.
- **Help lines.** "Default" for a loop is "It moves by itself. Pause it to look closely, or turn on slow motion to see each part of the movement." For SVG Path Animation it is Rotate In's line. The Try it help line is the kind's: loops "Change a setting and see the difference as it moves."; SVG Path Animation "Change a setting and the animation plays again."; do-it pages "Change a setting, then try it again or press Show me."; the scroll page "Change a setting, then scroll again or press Play." (on do-it and scroll pages a setting change plays nothing by itself; the shared script only replays pages that have Replay).
- **Pause (css)** means `data-hb-pause="css"` and **Pause (page)** means `data-hb-pause` without a value. The same goes for Slow motion and `data-hb-slowmo`.
- **Speed** reads Slow · Normal · Fast, and today's default stays Normal. For a duration, Slow is about 1.6 times and Fast about 0.6 times the default; for a rate (steps a frame, time multipliers), it is the other way round.
- **Swatches** use the Text & Typography palette, in this order, with each colour's name as its button's `aria-label`: Pink `#ff6f8b` · White `#f4f4f2` · Blue `#58a6ff` · Purple `#d2a8ff` · Green `#56d364` · Orange `#ffa657`. Every single colour picker here defaults to Blue `#58a6ff`, except Volumetric Smoke's, which keeps its own smoke colours (listed in its section).
- **Category line:** the pages have none today. NN is the page's position on the home page: `06.01 · 3D &amp; Advanced` (3D Model Orbit) to `06.18 · 3D &amp; Advanced` (3D Flip Card).
- **Titles:** four `<h1>`s differ from their home card names: Fluid / Liquid Simulation (card "Fluid Simulation"), Ray Marching / SDF Scene ("Ray Marching / SDF"), Cloth / Soft-Body Simulation ("Cloth Simulation") and Volumetric Smoke / 3D Noise ("Volumetric Smoke"). The titles stay as they are; pager links and See also links use the `<h1>`, as the page checks require.
- **Accent:** every page uses `--ui-accent:#3fd6c4`, the colour sixteen of the eighteen pages already have. 3D Flip Card changes from `#b98cff` (its card keeps its purple; see its section) and Morphing Blob, which has none, gets it.
- **Stage:** every page uses the default height. The old `--stage-h` values (620px; 480px, 420px, 400px or 380px on phones), the phone rules that made Chromatic Aberration, Glassmorphism Animated, Parallax 3D Tilt and SVG Path Animation `height:auto`, 3D Flip Card's own `clamp(360px,52vh,560px)` and Morphing Blob's `min(70vh,620px)`/`56vh` all go. A demo's own `.stage` rule keeps only what its content needs (`position:relative`, its background, flex centring, padding, `perspective`, `touch-action`, `cursor`); `flex:1`, `min-width`, `height`, `border` and `border-radius` go, because the page owns them. The shared `overflow:hidden` applies everywhere except the scroll page, whose own `overflow-y:auto` wins. `hb-dots` is used only on stages that paint one plain dark colour. On the shared stage (960×380 on a 1280×800 screen, 960×327 on a 1366×657 laptop, 707×440 on a tablet, 343×300 on a 375px phone and 288×300 on a 320px phone) three demos needed changes to fit: Glassmorphism Animated (cards in one row on phones), 2.5D / Pseudo-3D (a smaller scene) and 3D Flip Card (a card sized from the stage). Each was previewed at those sizes in headless Chrome.
- **Small text on stages:** eyebrows and small capitals get 11px and `font-weight:600`; card body text gets 13px at `rgba(255,255,255,.72)`; Georgia, Arial Narrow and italics go. These are the Ambient & Background sheet's card rules.
- **Class names:** no element on a stage may use the class names `seg` or `swatches`, because the shared stylesheet styles `.hb-page .seg` and `.swatches` for the Try it controls. No stage here uses them; the only `.seg` in this category is 3D Flip Card's old panel, whose rules go with the panel.
- **Slow motion** multiplies movements and the timers that wait for them, never holds, on every kind of page, including Show me runs (3D Flip Card's 1200ms hold stays 1200ms) and SVG Path Animation's plays (its 1200ms hold stays).

## Owner decisions and lessons that apply here

- **Stage text uses the site font.** Nothing here is a typing effect.
- **Pause stops at once, on every loop.** The ten page loops cancel their animation frame on `hb:pause` (the pattern below), which stops them at once. The two "css" loops are held by the shared class `hb-paused`, and neither has page timers. No loop here is a timer chain, so the Text sheet's `wait()`/`freeze()`/`thaw()` helper is not needed.
- **Reduced motion** greys out Slow motion (and Loop on SVG Path Animation), starts every loop paused, and runs nothing by itself: no Show me on arrival, no automatic scroll, and SVG Path Animation's Replay runs once as on Rotate In. Pause/Play, Show me, Reset, Play and Back to top still work when pressed. See "Reduced motion" below for what that removes from these pages.
- **Scroll and do-it pages show themselves once on arrival:** the shared script presses Show me or Play 400ms after load (not under reduced motion). The pages do nothing for this.
- **Long names in the top bar** ("Cloth / Soft-Body Simulation", "Volumetric Smoke / 3D Noise", "Image Distortion on Hover") are cut with "…" by the shared stylesheet; the pages do nothing.
- **Lessons from the Text & Typography reviews:** the `hb:pause` and `hb:input` listeners are registered at the top level of the page's inline script; the page reaches the player controls by their ids (`btn-pause`, `slow-tog`, `btn-demo`, `btn-reset`, `btn-play`, `loop-tog`), never by `data-hb-*`; a page never calls `pause()` or `play()` on a CSS keyframe animation; SVG Path Animation restarts its paths itself on every play (rebuilt hidden, a forced reflow, then drawn) and uses the pruning `later()`; Chromatic Aberration's typed text follows the typed-text rules (`trim()` decides blankness, blank falls back to the default, `textContent` only).

## Canvas and WebGL loops (Pause "page")

Ten pages move their picture with `requestAnimationFrame`: 3D Model Orbit, Canvas Particle Effect, Fluid / Liquid Simulation, WebGL Shader Animation, Noise-Based Motion, Ray Marching / SDF Scene, GPGPU Particle System, Cloth / Soft-Body Simulation, Volumetric Smoke / 3D Noise and Morphing Blob. Each follows Text on a Path; its section only adds what differs.

- The loop keeps exactly one pending frame in `raf`. The function that starts it, `start()`, returns at once when `raf` is set; otherwise it forgets the time of the last frame and requests a frame. On Cloth / Soft-Body Simulation it is called `resume()`, because that page's own `start()` rebuilds the cloth (see its section).
- The page listens for `hb:pause`, registered at the top level of its inline script. Paused: `cancelAnimationFrame(raf); raf=null;` and the picture on screen stays. Not paused: `start()` (`resume()` on Cloth), which carries on from the current state. The page keeps its own `paused` flag from this event; the old panel's Pause button, its label code and its flag handling go.
- Each page's frame gate stays as it is today (`if(dt<16)return`, 12ms on GPGPU Particle System).
- **Clocks.** Where the movement follows a clock, the page keeps its own, which adds up each frame's time (capped, and counted afresh from each start), so Play never jumps. Where a speed multiplies the clock inside a shader (Ray Marching's camera, Volumetric Smoke's rise), the page adds up the speed-weighted step itself, so a new speed never makes the picture jump; the sections say which uniform replaces which product.
- **The first picture:** the page draws a frame at load, before the loop starts, so a loop that is paused on arrival never shows an empty stage. The sections name the call.
- **While paused,** a setting change or a resize draws the picture again so the change shows, without moving anything. This is the loop rule "changing a setting while paused shows the new setting without starting the loop again". Most pages already do this ("repaint while paused"); the sections name the function. Listeners that watched the old `aside` for `input` now watch the Try it step for `click` and `change` (choice buttons send `click`).
- **Slow motion (page):** while the switch is on, each frame moves things a third of the usual step, or adds a third of the frame's time to the page's clock. It takes effect from the next frame. Something that jumps straight to the pointer (3D Model Orbit's Follows the pointer, Fluid / Liquid Simulation's pointer blob) is left alone; something that glides after it or is pushed by it (Morphing Blob's drop, Canvas Particle Effect's dots) moves at a third of its speed like everything else.
- **Pointer while paused:** the pointer's position is still recorded, but nothing on the stage moves until Play.
- The fps badges, the counters and the shader-source panels go (the pages show no code). The "WebGL is unavailable" and "shader failed" messages stay, in the site font. Context-loss handling stays exactly as today.

The browser tool (`tools/check-pages.mjs`) runs headless Chrome with `--disable-gpu`. A scratch check in that same Chrome found WebGL, WebGL 2 and `EXT_color_buffer_float` all available, and WebGL canvases appear in its screenshots, so its loop checks (the stage moves, Pause stops it, Play starts it) can see these stages.

## Do-it pages (Show me)

Four pages: Parallax 3D Tilt, 2.5D / Pseudo-3D, Image Distortion on Hover (step 1 "Hover it") and 3D Flip Card (step 1 "Click it").

- The body is `<body class="hb" data-hb-kind="do" data-hb-autoplay>`. Step 1's title and help line are in the section, and every do-it help line ends with ", or press Show me." (a rule for every lane). The player bar holds the Show me button, and the Reset button where the section has one, exactly as in the do-it/scroll plan (Task 2). 3D Flip Card also has Slow motion (css).
- **Show me** runs one example of the interaction, 2.5 to 3 seconds long, and returns the demo to rest. The run keeps one handle (its animation frame or its timer), so a second press restarts it cleanly and anything can stop it.
- **Stopping a run:** the page listens for `hb:input` at the top level of its inline script. Only if a run is under way (its own handle is set: its frame or its timer, or on Image Distortion on Hover its start time, because that page's render loop keeps `raf` set while the pointer rests) does it stop the run, leaving the visitor in control; otherwise it does nothing. A tap sends `hb:input` twice, for `pointerdown` and then for `touchstart`, the second after the page's own `pointerdown` handler has acted, so an unconditional stop would undo what the finger has just done (flatten a card, start fading a distortion). Hovering sends no `hb:input` (the shared script sends it for presses, keys, wheels and touches only), so on the three Hover it pages the page's own `pointermove` handler also ends a run that is under way, for trusted events only (`e.isTrusted`), before it acts on the pointer.
- **Reset** is there only where the demo keeps a state (2.5D / Pseudo-3D's camera, 3D Flip Card's turned card). Parallax 3D Tilt and Image Distortion on Hover return to rest by themselves.
- **Settings** apply at once to what they change (a depth, a colour) and play nothing; the visitor sees them at the next interaction or Show me.
- **Reduced motion:** nothing runs on arrival. Show me, Reset and the visitor's own pointer still work, so CSS rules that would stop them go (Parallax 3D Tilt's `transform:none!important`), while rules that only swap an animation for an instant change stay (3D Flip Card's face fade).

## Reduced motion for full-stage effects

Today almost every page handles reduced motion itself:

- script checks that draw one still frame and never start the loop (3D Model Orbit, Canvas Particle Effect, Fluid / Liquid Simulation, WebGL Shader Animation, Noise-Based Motion, Ray Marching / SDF Scene, GPGPU Particle System, Image Distortion on Hover, Cloth / Soft-Body Simulation, Volumetric Smoke / 3D Noise, Morphing Blob);
- CSS rules that remove the keyframe animations (Glassmorphism Animated, Chromatic Aberration), pin a card flat (Parallax 3D Tilt), or switch off every animation and transition on the whole page (`*{…animation:none!important;transition:none!important}` on Fluid / Liquid Simulation and Cloth / Soft-Body Simulation, which would also reach the shared page around the demo).

All of these go:

- the shared script now starts every loop paused under reduced motion, and a visitor who presses Play or Show me has asked to see the effect;
- the still-frame checks and the removal rules would stop Play or Show me from showing anything, and the browser check fails a loop that does not move after Play;
- the page-wide rules also change the shared page.

What stays: the still picture (every loop draws a full frame at load and is paused there on arrival), the scroll page's own "no easing under reduced motion" check, SVG Path Animation's rule that shows the drawing complete, and 3D Flip Card's face fade. The prompts keep their reduced-motion sentence, which is about the visitor's own site.

## 3d-model-orbit — 3D Model Orbit

- **Kind:** loop. The shape keeps turning; there is no end.
- **Description:** A lit 3D shape spins, or turns to face your pointer. Best for product views.
- **Watch it help line:** default
- **Player bar:** Pause (page) · Slow motion (page)
- **Sequence:** the WebGL loop as in the preamble (`render(ts)`, 16ms gate). Each drawn frame:
  - with Movement on Spins, `ry += SY*.01*k` and `rx += SX*.01*k*(Math.sin(clock*.0003)*.5+.5)`, where `k` is 1, or a third while Slow motion is on, and `clock` is the page's own clock (in place of today's `ts`, see the preamble), which adds `Math.min(dt,50)*k` for each drawn frame; the forward roll speeds up and slows down over about 21 seconds;
  - with Follows the pointer, `rx = mouseNY*1.2` and `ry = mouseNX*1.5`;
  - then `draw()`.

  **The first picture:** `draw()` runs once at load, after `init()` and `resize()`. **While paused,** every setting and a resize call `draw()` (today's `if(gl&&!raf)draw()` calls, which are now true only while paused).
- **Slow motion:** while the switch is on, both spin steps are divided by 3 and the page's clock adds a third of each frame's time, so the roll's speed wave takes three times as long too, from the next frame. Following the pointer is not slowed.
- **Reduced motion:** `motionOk` goes, with its one-frame branch at load and the "still follows the pointer" line in the `pointermove` handler (see the preamble).
- **Stage font:** no text on the stage; the WebGL message uses the site font.
- **Stage:** only the canvas. The fps and shape badges (`.hud`) go. `hb-dots`: no (the canvas clears to its own dark blue). Default height. `touch-action:pan-y` stays.
- **Phone fallback:** none needed. The largest shape, the ring, has 1,280 triangles and each pixel gets one light calculation; the canvas already caps the pixel ratio at 2.
- **Touch:** `pointerdown` also sets the pointer's position (today only `pointermove` does), so with Follows the pointer a tap turns the shape toward the finger and a sideways drag keeps turning it.

## scroll-driven-3d-rotation — Scroll-Driven 3D Rotation

- **Kind:** scroll. Scrolling inside the stage turns the cube; nothing moves on its own.
- **Description:** Scrolling turns a 3D cube from pose to pose. Best for product tours.
- **Step 1:** Scroll it — default help line: "Scroll inside the box, or press Play and it scrolls for you."
- **Scroller:** the `.stage` itself. Its own rule keeps `overflow-y:auto;overflow-x:hidden`, which wins over the shared `overflow:hidden`; no `data-hb-scroller`.
- **What scrolling shows:** the cube stays pinned in the middle of the stage while the stage scrolls through content four stage-heights tall. The scroll position, from the top to the end, moves the cube through four poses in turn: a quarter turn to the side, a forward tilt, growing larger, then turning round to show its back. It glides between them while Smooth follow is on. Scrolling back runs it in reverse.
- **Player bar:** Play · Back to top (the shared script runs both). No Slow motion.
- **Sequence:** unchanged: `scroll` → `onScroll()` → progress from 0 to 1 → `applyRotation(p)`, then `tick()` eases the cube toward its pose while Smooth follow is on, or `render()` sets it at once. The ResizeObserver stays. Back to top jumps the stage to its top, and the `scroll` event that causes brings the cube back to its first pose.

    for (let j = i + 1; j < particles.length; j++) {
      const dx = particles[i].x - particles[j].x;
      const dy = particles[i].y - particles[j].y;
      const d2 = dx*dx + dy*dy;

        const k = Math.min(5, Math.floor((1 - d2 / (DIST * DIST)) * 6));

      }

    ctx.stroke(path);
